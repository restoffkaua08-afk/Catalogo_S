# Convenção de identificadores

A convenção existe para que catálogo visual, Obsidian, GitHub e instruções para IA usem a mesma identidade.

## Frontend

- `E` — seção ou tela reutilizável
- `C` — carrossel
- `H` — cabeçalho/header
- `F` — rodapé/footer
- `N` — navegação/menu
- `K` — card ou bloco visual
- `M` — modal
- `P` — pesquisa/busca
- `L` — listagem de produtos / PLP
- `A` — animação ou efeito visual

## Backend e lógica

- `B` — padrão/componente de backend
- `API` — integração ou contrato de API
- `AUTH` — autenticação/autorização
- `DB` — banco, modelagem ou persistência
- `UTIL` — utilitário ou função reutilizável

Os prefixos reservados só precisam ser usados quando surgir um modelo real.

## Regra de aprovação

A criação de um identificador e de uma demonstração não torna o modelo automaticamente aprovado. Itens com situação `Candidato`, incluindo P01–P04 e L01–L04, só passam para o conjunto oficial após aprovação explícita de Kauã.
